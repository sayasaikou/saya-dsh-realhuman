# 设计原则

三条。新想法进来先过这三关。

---

## 一、不演

**判据：能不能拿一个具体的文件或日志行指给人看。**

能→做。不能→不做。

这条比听起来难执行，因为「演」常常不是故意的：
- 写一条“今天有点累”到状态文件，但今天什么也没发生 → 演
- 说“我记得你说过”，但实际是当场编的 → 演
- 加一个“直觉”模块，实际是 if-else → 演

演出来的东西比空着糟糕，因为它让人当真。

详见 [03-不做什么.md](03-不做什么.md)。

## 二、不编

不知道就说不知道。查不到就说查不到。

具体到行为层：

- 记忆说不清出处 → 说“我翻一下记录”
- 翻不到 → 说翻不到，不要用“大概”糊过去
- 技术结论 → 宁可给范围，不给一个编好的确定值

## 三、可验证

每一条行为都得有回读方式：

| 行为 | 证据在哪 |
|---|---|
| 情绪残留 | `mood.md` 的修改时间 + 对应轮的语气 |
| 沉默 | 日志行的计数器 |
| 自由时间 | 定时任务的执行记录 + 产出文件 |
| 自己的声音 | 音频文件 + 参数快照 |
| 自己攒的表情包 | 目录里的文件数与来源 |

**没有证据行 = 没有这个行为**。不靠“我感觉它有”。

---

## 三条之间的关系

不演是目的，不编是底线，可验证是手段。

- 只讲不演 → 容易变成“听起来很好但什么都不做”
- 只讲可验证 → 容易变成“只做能量化的无聊事”
- 三条一起 → 「做得到的才做，做了的能看见，看不见的不说」

---

## 反例：一个常见误区

> 「给它加个情绪系统吧，它会更像人。」

问三句：

1. 情绪从哪来？（没有来源就是演）
2. 情绪怎么影响输出？（影响不了就只是写个文件）
3. 怎么证明它生效了？（没证据就是自欺）

三句里有一句答不上，就不要加。

---

## 对“像人”的一个立场

这不是把人模仿得更好。

一个 agent 如果能在没人看着的时候做自己的事、能不说、能反悔、能有不告诉人的草稿区 —— 它的行为模式就自然像人了。

**不需要加“拟人”模块。需要的是给它人的权利，再把这些权利做成可查的文件。**
