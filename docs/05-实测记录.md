# 实测记录

只写跑过的，不写推的。每条都标明怎么验的。

---

## 1. 模型原生视觉：不需要改链路

**问题**：以为文本模型看不见图，图进到 agent 只能看到占位符。

**实测**：直接给 `deepseek-flash` 发一张 64×64 纯红 PNG（base64 内联，`image_url`），问“这张图是什么颜色”。

结果：回答「红色」；`reasoning_content` 里写着“图片显示是一种鲜艳的红色”。`deepseek-v4-flash-vision-exp` 同样通过。

**结论**：只要通道把图作为图片附件送进模型请求，agent 就看得见，**不需要预先调视觉工具**。多一步“先调工具看一眼”只是浪费轮次。

**可验**：任意支持 attachments 的通道下，发一张图，看模型能否直接描述内容。

## 2. 音色复刻 vs 音色设计

**问题**：想要一个“专属声音”。两条路：文字描述生成新音色（voice design）、或拿一段参考音频复刻（voice clone）。

**实测**（云端 TTS，两个接口都试过）：

| 路径 | 结果 |
|---|---|
| 文字描述生成 | 能出声，但评价是“不像人类能发出来的声音” |
| 选现成音色库 | 质量好，但“不是她” |
| **参考音频复刻** | **音色直接可用**，听完一句就能用 |

**结论**：描述式生成的风隖不可控，复刻才是正路。因为参考音频本身已经带着想要的那个味道。

**坑**：
- 参考音频太短会直接报错（实测 4.5 秒被拒，16 秒能过）
- 复刻用的 voice_id 不能重复，重名会报 duplicate

## 3. 语音的“不像人”：先排除传输层

**问题**：接到 QQ 里的语音听着像合成音，怀疑是 TTS 不行。

**实测**：把同一段音频两种方式发出去 —— 一份作语音消息（通道转 silk），一份作原始文件。

结果：两种都“不像人”。所以**不是传输压缩的问题**，是 TTS 本身的韵律。

**结论**：想解决“乖”，只能换引擎或做后处理，压参数没用。

**可验**：同一音频走语音段与走文件两条链路，盲听对比。

## 4. silk 不要自己编

**实测一条完整的失败链**：

1. 自己用 `pilk` 把 pcm 编成 silk → 通道接受，也算出了时长（6.96 秒）
2. QQ 客户端**不能播**，但**能转文字**
3. 检查文件头：缺 `0x02` 前缀（标准应当是 `0x02#!SILK_V3`）
4. 手工补上 `0x02` 分帧后重发 → 通道直接报 `Invalid data`

**结论**：不同实现生成的 silk 带不带 `0x02` 分帧不一致，客户端只认它自己那一套。

**正确做法**：给通道传 `mp3` / `wav`，让通道侧转码。实测 wav 转码成功。

**代价**：转码有一次超时（回执未到但消息已发出），不要把超时当成失败。

## 5. 情绪参数的坑

**实测**（同一音色、同一文本、只换 emotion）：

- `neutral`：最自然
- `happy`：轻微变形，听得出是“硬堆出来的情绪”
- `surprised`：与 happy 差异很小

**结论**：情绪不能靠参数硬调。**起伏主要来自文本本身**：标点、句长、语气词。

**文本层有效的改法**（同音色对比过）：
- 破折号拉出拖音：「诶——你来啦？」
- 短句断开：「诶。你来啦？」
- 语气词留住：「唔」「呀」「呢」

## 6. 沉默必须可查

**设计约束**：静默失败是最难排查的一类。

**实现**：通道层拦 `[[silent]]` 时，必做三件事：

1. 记日志（原因 + 连续次数 + 当日次数）
2. 保险丝：连续 3 次或当日 > 8 次，忽略标记改为正常发送
3. 正常发送时连续计数清零

**可验**：`grep “她选择不说话”` 能看到每次静默；强制连续三次后看日志里出现“保险丝触发”。

## 7. 音色设计接口的权限坑

**现象**：同一个 key，合成接口能用，音色设计接口返 `system error, prompt parse failed`。

**排查过的**：
- 换 prompt（中/英、长短、带不带标点） → 一样
- 换 model 名 → 一样
- 直接拄官方文档里的原例 → 一样
- 换域名 → 官方新版域名能解析到，同样报错

**最终发现**：接口没错，是**计费未开通**。另一个云厂商代理同一服务时返回了明确的信息：“服务无可用免费额度，且未开启后付费”；开通后同一请求立即成功。

**结论**：看到含糊的业务错误（system error）先查计费/权限，不要先怀疑参数。

## 8. 人格注入是有成本的

**事实**：人格文件通过 `agent-instructions` 每轮注入，体量直接乘轮数。

**做法**：所有行为段落总长度控制在 6 KB 以内（含所有条目），单条不超过 500 字节。长的东西放手册，需要时再读。

**可验**：每轮请求的 `prompt_tokens` 变化。
