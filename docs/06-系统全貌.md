# 系统全貌

这套东西不是单个插件，是四层。装的时候从下往上。

```
┌────────────────────────────────────────────────┐
│  宿主：DeepSeek Harness ≥ 0.2.1                  │
│  agent-instructions / llm / tools / sessions     │
└───────────────┬────────────────────────────────┘
                │
     ┌──────────┴───────────┐
     │                      │
┌────▼─────────┐   ┌────────▼─────────┐
│ 通道层         │   │ 像人层（本仓）      │
│ 收发消息         │   │ 状态 / 沉默 / 声音   │
│ 不进本仓         │   │ 自由时间 / 作品     │
└────┬─────────┘   └────────┬─────────┘
     │                      │
┌────▼──────────────────────▼─────────┐
│ 数据层（磁盘上的文件）                      │
│ 人格 / 记忆 / 状态 / 自己的东西            │
└────────────────────────────────────┘
```

---

## 四层各是什么

### 1. 宿主

不用改。但要注意两条：

- 插件 `engines.dsh` 写 `>=0.2.1-0`，低于这个装不上
- 人格文件是**每轮注入**的，体量直接乘轮数

### 2. 通道层（不在本仓）

只要满足两件事就能用：

1. 能把入站消息丢给 agent（文本，最好带图片附件）
2. 能把 agent 的输出发出去

参考实现：OneBot 11 通道（公开仓 `dsh-napcat`），或官方 Bot 通道。

**本仓只在通道层上挂一个钩子**：发送入口拦 `[[silent]]`。如果不想改通道插件，就把它当可选功能。

### 3. 像人层（本仓主体）

| 模块 | 做什么 | 状态 |
|---|---|---|
| 状态 | `mood.md` / `pending.md` 的读写与注入 | 已在生产跑 |
| 沉默 | `[[silent]]` 拦截 + 日志 + 保险丝 | 已在生产跑 |
| 声音 | 文本 → 云端 TTS → 通道发语音 | 已在生产跑 |
| 自由时间 | 允许自己排“没人的时间” | 已在生产跑（靠定时任务） |
| 自己的东西 | 自己的表情包库 / 作品集 | 已在生产跑（目录级） |
| 视觉 | 不需要改：模型原生支持，通道把图当附件送进去 | 已实测 |

### 4. 数据层

全部是**磁盘上的文件**，不用数据库。好处是：能直接看、能直接改、能进版本库。

```
persona/
  AGENTS.md            人格（每轮注入）
  手册/                 长手册（需要时再读）
state/
  mood.md               当前情绪
  pending.md            没完的事
  self.md               它自己的地方
memory/
  shared.md             跨会话记忆（人工可读）
  sessions/             会话原始记录（宿主自己管）
works/
  my-memes/             自己的表情包
  pieces/               作品集
```

---

## 为什么这样分

**分层是为了能单独换。**

- 换通道：不动像人层
- 换 TTS 引擎：不动其他
- 换模型：只影响“说话像不像”，不影响“行为像不像”

## 最少的可跑组合

只想要“不会每轮从零开始”：

- 宿主 + 通道 + **状态层**（一份文件 + 一段人格）

这就够了，不需要任何插件代码。
