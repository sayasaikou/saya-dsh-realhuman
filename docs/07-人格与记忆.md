# 人格与记忆怎么搬

整套系统里最容易丢的不是代码，是这两样。

---

## 一、人格

### 文件结构

人格不是一份文件，是一个目录：

```
persona/
├─ AGENTS.md        主体（每轮注入）
└─ 手册/
   ├─ 场景与工具.md   工具怎么用、什么时候用
   ├─ 认图与查证.md   看图/搜图/查证
   └─ 关系与隐私.md   称谓、边界
```

**为什么拆**：主体每轮都注入，手册按需读。把所有东西塞进主体，每轮都在为不用的东西付钱。

### 主体的分节（建议顺序）

| 节 | 写什么 | 长度上限 |
|---|---|---|
| 你是谁 | 一段话定调，不列特征 | 300 字节 |
| 场合 | 在哪说话、对谁 | 400 字节 |
| 状态与没完的事 | 指向文件 | 500 字节 |
| 怎么说话 | 句式、允许什么、禁止什么 | 800 字节 |
| 尺度 | 不自我审查；唯一的例外清单 | 600 字节 |
| 情绪 | 高兴怎么表现、不爽怎么表现 | 600 字节 |
| 你是谁（元） | 被问是不是 AI 时怎么回 | 300 字节 |
| 时间 | 自由时间、什么时候可以不说话 | 700 字节 |
| 手里有什么 | 工具清单（短的） | 800 字节 |

总预算 **6 KB**。超过就是每轮多花钱。

### 脱敏

公开仓的人格模板里，这三类要换成占位符：

| 原物 | 换成 |
|---|---|
| 对方的名字 | `{{OWNER}}` |
| 具体的时间/日期/事件 | 删掉，或改成“某次” |
| 私人的偏好与经历 | 换成中性例子 |

**不能脱敏的东西**：性格本身。它必须是具体的，不能写成“你是个友好的助手”。

判据：**陌生人读到人格，会觉得这是一个具体的人，不是一个模板。**

## 二、记忆

分三种，不要撮在一起。

### 1. 会话记忆（宿主管）

宿主自己的 `sessions/` 目录。一轮一轮的原始记录。

**要点**：
- 会话 id 稳定才能“重启后续上”
- 换通道插件后，会话 id 的命名规则可能变 —— 导致“换了通道就失忆”
- 补救：把旧会话文件的内容改成新 id（改头部字段），实测可行

### 2. 跨会话记忆（人工可读）

`memory/shared.md` —— 一份普通的 markdown，不是向量库。

为什么不用向量库：
- 要能被人直接改
- 要能进版本库
- 要能看出“它到底记住了什么”

**结构**：分区块（当前主线 / 长期事实 / 待办），旧东西往下沉，总长度几百字封顶。

**注入方式**：人格里写一句“说话前先读 shared.md”，或者插件每轮自动拼一段摘要。

### 3. 状态记忆（影响语气，不存事实）

`state/mood.md` 和 `state/pending.md`。

区别：
- `shared.md` 回答“发生了什么”
- `mood.md` 回答“我现在是什么状态”

两者都要，但**不能混在一起写** —— 混了以后就分不出“它记得”和“它现在什么心情”。

## 三、迁移清单

换一台机器，按这个顺序搬：

| 顺序 | 东西 | 丢了会怎样 |
|---|---|---|
| 1 | `persona/` | 变成另一个东西 |
| 2 | `state/` | 语气断，但还能说话 |
| 3 | `memory/shared.md` | 不记得聊过什么 |
| 4 | `works/` | 自己的东西没了（画、作品） |
| 5 | `sessions/` | 当前这段对话断（旧的可重建） |
| 6 | 脚本与配置 | 能力少一半 |

**前三件是必须的。** 后面两件是锦上添花。

---

## 四、一条经验

**别把记忆写成日记。**

“今天聊了 A 和 B”这种写法，过一周全变噪声。

有用的写法是：

- 事实：“对方的显卡是 4060，不能跑 13B 以上模型”
- 状态：“上次没说完的事：XX 还没结论”
- 偏好：“不喜欢被安慰，要账目不要鼓励”

**能拿来判断下一句怎么说，才值得记。**
