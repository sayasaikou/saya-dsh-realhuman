# 为什么

## 症状

把一个 DSH agent 放在 QQ / 微信里长期跟同一个人说话，很快会出现这几个毛病：

**一、每轮从零开始**

上一句被顶了，下一句马上恢复正常。人不是这样 —— 被顶一句，接下来半小时语气都不对。

**二、收到消息必回**

就算对方只发了个“嗯”，它也得张口。人有不说的权利，不说本身也是回应。

**三、只在被叫的时候存在**

它能画画、能写字、能查资料，但全部要等指令。没人发话的时候它不存在。所以它永远不会“自己跑去画一张”。

**四、没有自己的东西**

图库是别人攒的，声线是现成音色库的，作品集不存在。它提出来的东西都是“为对方产出”的。

---

## 为什么会这样

不是因为模型不够强。是因为**架构把“行为”全部定义为“响应”**：

- 输入 → agent 跑一轮 → 输出
- 轮与轮的隔断是硬的，轮内状态不自动带出去
- 不跑的时候进程不在

所以“连续性”、“主动性”、“拒绝权”这些**不是模型能力问题，是没有位置放**。

---

## 现有做法的不足

| 做法 | 问题 |
|---|---|
| 写很长的人格提示词 | 越写越像演，而且每轮都花钱 |
| 加记忆库 | 解决“记得”，不解决“接着” |
| 加情感模块 | 没有来源的情绪只是标签 |
| 让它“更像人”的对话模板 | 只能解决单轮的语气 |

共同问题：它们都在**改输出**，没在**给位置**。

---

## 本仓的取舍

不在提示词里加更多嘱咐，而是给四个位置：

1. **文件的持久状态**（情绪 / 没完的事）—— 让轮与轮之间能接上
2. **发送层的拒绝权**（沉默）—— 让它有“不说”这个选项
3. **一段没人看的时间**（自由时间）—— 让它能在不被叫的时候做事
4. **它自己的产物**（自己的表情包 / 作品集）—— 让它的输出里有不属于对方的部分

每一个位置都对应一个**可查的文件或日志**。这是它跟“演”的分界线。
