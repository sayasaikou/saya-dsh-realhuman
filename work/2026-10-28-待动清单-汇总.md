## 1 · 她自己点名的三样（P0，她说了「缺了就只能靠记得」）

### 1.1 文件柜 —— 能翻自己做过什么 `[ ]`

- **要什么**：一个工具，把 `work/pieces/` 和 `work/realheart/` 里已有的产物按时间列出来，每件一句「这是什么」。
- **不新建目录、不新建格式** —— 就是给已经在的东西一个入口。
- **实现**：新工具 `rh_cabinet`。递归扫两个目录，按 mtime 倒序；每件取一句描述：
  优先用文件首个标题行（`# xxx`），没有就用文件名 + 类型；**取不到就写「没写说明」，不编**。
- **判据**：问「我什么时候做的克拉尼图」，能答出时间 + 文件路径；问「10:52 我做了什么」，能列出那一刻前后的产物。
- **为防什么**：今天她把自己做过的事记错了一次时间，只能去查 mtime。

### 1.2 pending 未完成的，每轮出现在她眼前 `[~]`

- **已做**：0.2.0 的注入里已有【没完的事】一段（未完成条数 + 最近 3 条 + 两个数的样本状态）。
- **还差**：① 实机验；② **存量 9 条基线导入**（标 `at_unknown = true`，否则它们永远进不了兑现耗时）；
  `勾过 0 条` 这个现象本身就是「它从来没在她眼前出现过」的证据。
- **判据**：导入后下一轮注入里能看到那 9 条中的未完成项；勾掉一条后它从注入里消失。

### 1.3 `rh_changes` 每条带「改之前的原样」 `[ ]`

- **要什么**：读账本时，每条能带一小段改前的原文，不用 diff 引擎，前后各几行就够。
- **实现**：`rh_changes` 加参数 `with_before`。拿这条记录对应文件的最新 `.bak-*`，按标题/时间戳定位同一段，
  摘前后各 3 行；**定位不到就明说「没找到改前版本」**，不做相似度猜测。
- **判据**：问她「20:20 那条改之前是写的什么」，能给出原文片段；没有备份的条目要老实说没有。
- **为防什么**：今天她认了三次错。认错的前提是能看见自己原来怎么说的。

## 2 · 防静默失效（发布前后都该做，坏了不报错的那类）

- [ ] **注入预算压力测试** —— 用真实量级的记忆卡跑一次注入，断言心情小节仍在；被裁时日志要有一行。
  现在只测过「记录少时能渲染」。
  验：把预算压到 200 字，心情小节被裁时会报一行，而不是默默消失。

## 3 · 沉默那条金线（她标了「这份清单里最值钱」）

## 6 · 插件工程化（「能给别人用的插件」还缺什么）

> 这一段回答的是他的问题：作为插件，还差什么。分两半：**能装能用**（6.1–6.5）与**像个正经项目**（6.6–6.8）。

### 6.1 设置入口 `[ ]` —— 先查，别急着造

- **现状**：所有配置只能改 profile 的 `cordis.patch.yml`，要会 YAML、要重启，装的人第一步就卡这。
- **两条路**：
  - (a) 宿主是否会给「声明了 config schema 的插件」自动渲染设置界面；
  - (b) 自带一个极简面板（`dsh-soul` 就是把语气/表格/emoji 做成设置页的，照它的做法）。
- ⚠️ **先查 (a)**：宿主若有统一入口，自己再造一个就是重复造轮子，还会让配置分两处。
- **面板只放六项**：观测页端口 / 绑定地址 / 注入开关 / 注入预算 / 口令重置 / 数据目录与导出。
- **绝不放**：调情绪的、调她语气的、任何「她今天状态如何」的输入框。那是操纵，不是设置。
- 判据：改端口不用编辑 YAML；关掉注入不用重启。

### 6.2 `rh_doctor` 一条命令自检 `[ ]`

查七件：依赖（python3 / zstd）、`stateDir` 是否可写、观测页端口有没有被占、口令有没有落进日志、
`pending.md` 与流水是否一致、今天注入成功过没有、账本里有没有解析不了的行。
判据：任何一条不通过，都打印「哪儿坏了 + 怎么修」，不是只报红。

### 6.3 升级与迁移 `[ ]`

0.1.x → 0.2.0 要处理三件：`pending` 存量基线导入、旧心情行没有 `why_kind`（默认按 `ref` 处理，代码已兼容）、
`stateDir` 布局变化。加一个 `stateDir/.version` 标记，一次性动作写进日志。
判据：从 0.1.1 升上来，那 9 条自动进账并标 `at_unknown`，不丢一条。

### 6.4 多实例与端口 `[ ]`

两个 profile 同时装会抢 8098。要有占用检测 + 自动换端口 + 把最终端口记进 `config.json`。
判据：第二个实例自动用 8099，并在日志里说清「8098 被占，改用 8099」。

### 6.5 卸载与数据边界 `[ ]`

卸载默认**保留**数据并打印数据在哪；删除必须显式 `--purge`。
判据：卸载后 `stateDir` 还在、观测页进程停了、profile 的 bundles 里那一行没了。

### 6.6 日志与口令 `[ ]`

所有 `catch` 必须落日志（「坏了不报错」是这套东西最大的风险）；口令在任何日志里都不出现，配一条自检脚本。
判据：故意把口令写进错误分支，自检能抓出来。

### 6.7 工程件 `[ ]`

`CHANGELOG.md`、`npm publish --dry-run` 流程写进 README、版本号语义、`engines` 在装的时候校验、
CI 跑那两个测试文件（可选，但 GitHub Actions 免费）。

### 6.8 集成测试 `[ ]`

现在只有纯函数单测（8 项）。缺「真启动一次插件」的测试：断言四个工具都注册上、注入段落真的出现、
`pending.md` 首次渲染成功。这条比再加十个纯函数测试有用。
