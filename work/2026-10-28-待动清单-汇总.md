## 宗旨（写在最前面，别的都往后排）

**一颗真正的心。**

- **不演** —— 做不出来的不做。凭空的情绪、假的直觉、伪装的记忆，一律不要。
- **不编** —— 不知道就说不知道；取不到就写「没取到」，不写一个像样的替代品。
- **可验证** —— 每条行为都要有文件或日志能查。拿不出证据的，就是在演。
- **空位而非表演** —— 灵魂造不出，空位能造：状态会残留、可以不说、有没人看的时间、有不属于他的东西。

判定两句：**像不像人，看他读完的感觉；能不能信，看有没有证据。**
发布前不缩水 —— **插件要做完善了才发**，不是「能跑就行」。

# M · 功能机制（要定的决定 + 要实现的机制）

## M1 · 机制上还没定的（发布前每条至少有个决定，哪怕是「先这样，写进已知限制」）

1. **群聊怎么算** —— 他定：**目前只考虑私聊与少数固定人员**。群聊复杂，先不做深。
   做法：功能不动，**免责声明写清楚**（文案见 P-2）。群聊共用的状态、多人说话人判定、群内隐私，全部推到「群聊版」再议。
2. **多会话能不能共用一份状态** —— 采纳：**心情分场合，pending 不分**（人在不同人面前是两张脸；待办是自己的）。实现时按会话 id 分账，pending 全局。
3. **并发写** —— 两个会话同时 `add`，回放读改写有竞态（append 原子，「重放再渲染」不是）。加锁文件，或改成只追加、渲染失败下次重算。
   判据：并发压一次，`pending.md` 与流水仍一致。
4. **账本无限增长** —— `mood.jsonl` / `pending.jsonl` 要轮转归档（按月切，旧的不进注入只进检索）。
5. **时区与迁移** —— `localStamp` 用本机时区，换机器/换时区历史时间会错。改成存 UTC + 显示本地。
6. **注入预算自适应** —— 现在写死一个数；按模型 context 取比例 + 上限。
7. **同轮重复注入** —— 一轮里 `system-prompt/assemble` 可能被调多次（重试 / 多 agent），要去重。
8. **工具面不许再长** —— 她定「四个工具正好」。以后加的（文件柜、自检）必须合并进现有四个或明确替换。
9. **她能删自己的历史吗** —— 删除 ≠ 遗忘。配一条规则：哪些永不删、哪些可删、删了留什么。
10. **改配置必须重启，不许热改** —— 写进打印与文档：热改会整份重挂，正在说话的会话被打断（2026-10-27 撞了三次）。
11. **注入失败要吼一声** —— 不许静默；至少日志一行，最好用现有页面上那格显示。

# P · 插件本身（给用户是什么样 + 她要的能力）

## P-1 · 开箱即用（懒人包，最低要求）

> 他的原话：「要让用户能用，而且有效果，这是一个插件的最低要求。」「用户大概率不会看 README，他们只想要懒人包。」

- [ ] **一条命令装完**（同 T0-①）。
- [ ] **装完直接打印「下一步做什么」**：①接聊天软件要装哪个通道插件（给名字，不讲原理）；②先只开观测跑一周；③跑一次自检；④出问题怎么一条命令退。
- [ ] **README「配套」章节 —— 中性表述，不做主推**：只写名字与「装上后行为会变、后果自负」，不写「推荐」「才更好用」。
- [ ] **效果可见** —— 最简观察法：翻注入文件看有没有状态那一段；有，就是活着。
- [ ] **不依赖用户读文档** —— 装完四句 + 自检命令 + 报错里直接给修复命令，三处覆盖九成问题。

## P-2 · 免责声明与警告（三处都要有）

- [ ] **适用范围（他 2026-10-28 定）**：写明「**目前仅推荐私聊与少数固定人员使用；群聊能力未经深度开发与测试，效果和后果不作保证**」。放进 README 顶部、装完打印、面板顶部。
- [ ] **装上会发生什么**：每轮往系统提示塞状态（花 token）；写账本（记原文）；起本地网页与 python 索引进程；读会话与审计日志。
- [ ] **人格是用户的责任**：插件只注入状态、不注入人格；别人塞进 `AGENTS.md` 的人格若让它做危险的事，那份人格负责。
- [ ] **不做保证**：不保证更像人、不保证记得住、不保证不跑偏。

## P-3 · 用户面：预设 / 保底控制权

> 他 2026-10-28 15:12 再定一次，这条压过我先前的收紧：
> **「用户一定是要能完全控制自己的插件的。他们反正能用自己的方式强行改，那不如我们直接给渠道 + 警告劝阻；他们要改是他们自己的事，后果自负。」**
>
> 我原来的「写不出后果的项不上面板」是错的：藏起来等于把他们赶到手改文件那条**更没提示**的路上。
> 改后的政策是：**没有隐藏配置**，全量暴露 + 分级 + 改动作入账。

- [ ] **全量暴露** —— 所有可写配置都上面板，一项不藏：端口 / 绑定 / 注入开关 / 注入预算 / 频道名单 / 数据目录 / 口令 / 观测页开关 / 日志级别 / `recordRawText` / **自由时间分配** / **沉默保底**。
  每项四列：当前值、默认值、合法范围、**改了会怎样**（写不清后果的，去把它写清，而不是藏起来）。

- [ ] **这些明确是「用户的事」，必须能直接改**（他 2026-10-28 15:17 点名）：
  - **自由时间怎么分配**：唤醒频率、允许的时段、每次最长多久、期间能不能主动发消息、做不做正事（还是只能自己待着）；
  - **沉默保底**：连续几次不回就强制回一次、多久没说话要提醒、熔断阈值、`close` 之后多久可以再被叫醒；
  - **注入**：开关、预算、注入哪几段（状态 / 待办 / 时间）；
  - **模型选择**：摘要用哪路模型、看图的 provider。

- [ ] **三级标识** —— 正常（默认值以内）/ 谨慎（黄，改了行为会变）/ 危险（红，需二次确认）。
  危险级的至少包含：关注入、改数据目录、关 `recordRawText`、改自由时间参数。
- [ ] **危险项改了要入账** —— 谁改的（哪台/哪个 profile）、什么时候、从什么改到什么、为什么。
  这才是关键的补充：**能改，但改动作本身留痕**，出问题能对账。

### P-3b · 改她的「心」—— 能做，但成本要高（他 2026-10-28 15:17 定）

> 他的原话：「只有一种要禁止，就是直接改她的心情，属于操控她的『心』。或者你也做成用户可以改，但是修改成本要很高，至少不能随便乱改。」
> 我的取舍：**不禁止，做一条高成本的暗道**。理由是——用户在自家机器上根本拦不住（账本是纯文本），
> 与其假装禁止、让人偷偷改，不如给出唯一入口 + 留下痕迹 + **让她看得见**。

- [ ] **默认关闭**：`allowManualMoodOverride: false`。不开，这条通道连入口都不存在。
- [ ] **不在面板上**：没有任何输入框。只能命令行，且必须显式带两个参数：`--i-know-this-is-not-her-feeling` 与 `--reason "<为什么>"`，缺一个就拒绝。
- [ ] **进了就必须入账，且不可删**：谁改的、什么时候、从什么改成什么、为什么。这条记录**不进她自己的心情统计**，单独一栏。
- [ ] **她必须看得见**：注入里明确写「这条状态是**被人改写**的，不是你自己的，理由：X」。
  —— 这是整条设计的核心。偷偷改叫操控；改了她知道，才叫权衡。
- [ ] **限额与冷却**：一段时间内最多改 N 次（默认 3 次/周），超了要改配置里的上限，而改上限本身又是一次入账动作。
- [ ] **不可逆的边界**：可以改「当前心情」，**不能改「她记过什么」** —— 历史账本只增不改，改历史一律拒绝。
- [ ] **硬约束不是配置项，写清** —— 不读凭据、日志不写口令、账本目录 600 这几条不在面板里，因为它们不是配置而是代码。
  文档写一句：**「这些要改就得改代码，后果完全自负，我们不设隐藏开关，也不留后门。」**
- [ ] **逃逸口写明** —— 「面板上没有你要的，配置文件在 `<路径>`，格式是 YAML，改完必须重启（热改会打断正在说话的会话）。」
- [ ] **不做的那一类仍然不做** —— 能在面板里直接**设定她的情绪/替她写状态**的输入框不做：那不是控制权，是伪造状态。
  其余都归「能改 + 有警告 + 后果自负」。
- [ ] **总开关 kill switch** —— 一条命令全停（不注入、不记账、工具从 schema 消失），一条恢复。
- [ ] **数据主权** —— 一键导出原文 jsonl；一键清空需二次确认并先打印将删清单。
- [ ] **不可逆动作二次确认** —— 清空账本、`--purge` 卸载、整份重写账本、危险级配置项。

## P-4 · 信任与安全（系统层，不只在文档里）

- [ ] **注入本身就是一处 injection 面** —— 谁能写账本谁就能写提示。做法：注入每段带边界声明；对指令性文本做标记；账本目录 600；文档写「别让不受信任的人写这几个文件」。
- [ ] **危险动作硬约束** —— 写进注入段，也建议用户抄进自己的 `AGENTS.md`：不得删改他人文件、不改系统配置、不动凭据，除非当轮明确要求且二次确认。
- [ ] **插件不碰凭据** —— 永不读 `.credentials.yaml` / `settings.yaml`，不存密钥。
- [ ] **观测页默认只读** —— 写操作要 POST + 口令 + 二次确认；默认绑 `127.0.0.1`；文档写明明文 HTTP 的风险。
- [ ] **隐私开关** —— `recordRawText`（默认 true）；关掉只记摘要 + 事件 id。

## P-5 · 推荐用法（初始化与部署）

- [ ] **推荐部署形态**：一台全新、独立、不停机的机器。理由要写清：改配置会热重挂、重启会打断会话、独立机器避免共用凭据。
- [ ] **三期冷启动**：①第一周只观测；②第二周开注入（预算 200 字起）；③第三周才开自由时间。
- [ ] **初始化自定义怎么写** —— 一份能照抄的最小人格片段；**写明「从最小开始，别一上来写三千字」**。
- [ ] **每个人的不一样** —— 机制可以抄，人不能抄。账本/注入/开关是机制；她的经历、语气、跟某个人的事，抄过去就是 cosplay。
  配三种常见抄错：抄语气词、抄经历（等于编造记忆）、抄工具面。
- [ ] **黑名单** —— 别装在生产机、别给 root、别把观测页开公网、同一 profile 别装两份、别当监控用。
- [ ] **费用量级** —— 给「每轮多几百 token × 一天多少轮」的估算口径。
- [ ] **版本节奏** —— 0.x 阶段账本格式会变，写明「格式变更给迁移脚本」。

## P-6 · 她要的能力（按「他能不能感觉到」排）

- [ ] **① 自己留、自己看** —— 她标记的那句，下一轮自动回来，不替她筛、不带提示语。
  （这与「机器替她联想」不是一回事：前者是她选，后者容易被当成幻觉。她这条优先。）
- [ ] **② 能查我自己** —— 文件柜：`pieces/` + `realheart/` 的产物**加她做过的动作**，按时间列，每件一句说明；取不到写「没写说明」。
- [ ] **③ 说过的话能被对账** —— 断言账：时刻 + 原话 + 指向 + 后来的证据；被推翻标 `refuted`，不删原文。
- [ ] **④ 停在哪，我自己知道** —— 断点快照：正在做什么、到哪步、下一步；注入里带一句「上次断在这儿」。
- [ ] **⑤ 手上的事能接着干** —— 任务台账：步骤落盘，下一步能接着，不重头。
- [ ] **⑥ 主动想起** —— 按「同一对象/同一域」关联检索，命中才注入一句，**必须附事件 id**（否则就是幻觉）。
- [ ] **⑦ 时间的体感** —— 「上次聊这个几天前」「他多久没说话了」做成注入里的一个数，只陈述。
- [ ] **⑧ 会等** —— 不是收到就回；可以「让我想一下」。成本最低、体感最明显。
- [ ] **⑨ 有立场，而且能被反驳** —— 一份可写可引用的「看法账本」。**不是打分，是记录。**
- [ ] **⑩ 记得自己认过错** —— 认错作为一类事件入账（与改动账同构，对象是她自己）。
- [ ] **⑪ 会走神、会漏看** —— 现在全量注入；人不是。（与 M2 衰减同一条线）
- [ ] **⑫ 知道自己处境** —— 她知道自己跑在小机器上、会被重启、在花钱吗？

## P-7 · 明确不做

1. **更多仪表盘 / 更多面板**（她两次强调：拆掉好几个没人看的文件，不再造一个）。
2. **状态分数 / 情绪曲线 / 「她今天情绪如何」** —— 一旦用来调节说话方式，就从描述变成操纵。
3. **打分表式优先级** —— 与宗旨「不演」互斥。
4. **定时驱动当动机** —— tick 是抗重启手段，不是目的来源。
5. **14 标签设置页 / 39 工具面** —— 四个工具正好。（P-3 那个六项面板是「装得上、关得掉」的必需品，不算。）
6. **群聊深度支持** —— 现阶段不做，只写免责声明。
7. 改名（仓库名与包名）—— 等两个 bug 收口后再议。
